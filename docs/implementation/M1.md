# M1 — Real Coding Agent in Isolated Worktrees

Status: **implemented and verified locally** (tests, typecheck, build). Live
OpenAI/Anthropic execution and real GitHub push/PR creation require credentials
that are not committed to the repository; see
[Manual verification](#14-manual-verification).

This document describes the M1 milestone of TaskFleet: turning the orchestration
skeleton into a coding agent that edits a real repository checkout, verifies its
work, commits it, pushes it, and opens a pull request — with every step persisted
and streamed to the existing dashboard.

---

## 1. Objective and scope

M1 delivers one complete, honest coding loop:

```
task → isolated worktree → coding agent edits files → diff → tests
     → commit → push → GitHub PR → artifacts + events + UI
```

In scope:

- A real `coding-agent` backed by an LLM with native tool calling.
- Per-run Git worktrees with path-jail enforcement.
- File read/list/search/write/patch tools and allowlisted command execution.
- Automatic test execution after the agent finishes.
- Real diffs, changed-file lists, commit SHAs, pushes, and GitHub PRs.
- Persisted artifacts and ordered lifecycle events, including SSE delivery.
- Run/task UI that shows branch, worktree, diff, files, tests, commit, and PR.

Out of scope (deferred, do **not** treat as complete):

- M2 features (CI feedback loop, review-comment routing, merge automation).
- Container-level sandboxing. M1 isolates files and Git state, not the process
  or the network; see [Limitations](#13-limitations-and-security-notes).
- GitHub OAuth, multi-tenant auth, and horizontal scaling of workers.
- Autoscaling, queues, or distributed execution.

The existing `research-agent`, API, persistence layer, security scanner, and
dashboard remain intact. M1 extends the architecture rather than replacing it.

## 2. Architecture overview

```
React dashboard
   │ REST + SSE
Fastify API
   ├── RunService ─────────────── lifecycle owner
   │     ├── WorktreeService ──── git worktree / diff / commit / push
   │     ├── AgentRegistry
   │     │     ├── ResearchAgent
   │     │     └── CodingAgent ── LLM tool-calling loop
   │     │            └── WorkspaceTools ── path jail + allowlisted commands
   │     ├── test-runner ──────── detection + execution
   │     ├── RunStore ─────────── Prisma persistence
   │     └── RunEventBus ──────── SSE fan-out
   └── GitHubClient ───────────── pull request creation
```

Key design rules:

- **One run, one branch, one worktree.** Branches are `taskfleet/<runId>`; the
  worktree lives at `<worktreesRoot>/<runId>`. Retries and concurrent runs never
  share files.
- **The agent never owns Git.** It edits files and runs allowlisted commands.
  Diffing, committing, pushing, and PR creation are owned by `RunService`, so a
  model cannot fake a commit or a PR.
- **No fake success.** If a provider cannot call tools, the run fails with
  `TOOL_CALLING_UNSUPPORTED`. If GitHub is not configured, the commit stays local
  and the PR is recorded as `unavailable`; no URL is invented.
- **Artifacts are evidence.** Diff, changed files, test output, commit, and PR
  metadata are stored in `RunArtifact` and exposed through the API.

| Column      | Type      | Purpose                                        |

| `runId`     | `String`  | Owning run (cascade delete)                    |

## 4. Worktree isolation

`apps/api/src/worktrees/worktree-service.ts` now supports:

- `ensureForRun(taskId, runId)` — idempotently creates or resets
  `taskfleet/<runId>` at `<worktreesRoot>/<runId>`.
- `reset(worktree)` — `git reset --hard HEAD` + `git clean -fd`.
- `remove(worktree)` — removes the worktree but keeps the branch for a PR.
- `diff(worktree)` — stages everything, then returns a real unified diff,
  changed-file list, and a truncation flag.
- `commit(worktree, message)` — commits with the configured Git identity and
  returns the SHA.
- `push(worktree, { remoteUrl, token, branch })` — pushes `HEAD` to the run
  branch.
- `status(worktree)` — branch name, clean/dirty state, changed files.
- `list()` — Git worktrees, including legacy per-task ones.

Safety properties:

- IDs are validated against `^[A-Za-z0-9_-]+$` before path construction.
- `remove()` refuses paths outside the managed worktrees root.
- `ensureForRun()` refuses to reuse an existing directory that is not a Git
  worktree.
- The token is injected into the HTTPS remote for the push command only, and
  both the token and authenticated URL are redacted from errors.

Legacy `create(taskId)` / `branchForTask()` remain for backward compatibility.

### Path jail

`apps/api/src/worktrees/path-jail.ts` resolves every agent-supplied path against
the worktree root and rejects:

- absolute paths and Windows drive paths,
- `..` traversal and NUL bytes,
- `.git` access (unless explicitly allowed for listing),
- symlink escapes, verified with `realpathSync`.

`WorkspaceTools` wraps jail failures in `ToolError` so the agent receives a
structured, non-fatal tool error instead of crashing the run.

## 5. Coding agent and tools

### `CodingAgent`

`apps/api/src/agents/coding/coding.agent.ts`

- Requires `context.workspace`; otherwise fails with `WORKSPACE_REQUIRED`.
- Refuses to run when the provider lacks native tool calling.
- Runs a bounded multi-step loop:
  1. send system prompt, conversation, and tool schemas to the provider,
  2. execute returned tool calls,
  3. append tool results,
  4. repeat until `finish` or a limit is reached.
- Enforces `maxSteps`, `maxTokens`, and `maxToolCalls`.
- Honours `AbortSignal` between steps and inside commands.
- Emits `agent.edit` progress for writes/patches and `agent.progress` for reads,
  searches, commands, and tests.
- Returns a structured `CodingOutput` (summary, workspace, branch, edited files,
  commands, tests, steps, tool calls, provider, model).

### `WorkspaceTools`

`apps/api/src/agents/coding/tools.ts`

| Tool            | Behaviour                                                        |
| --------------- | ---------------------------------------------------------------- |
| `read_file`     | UTF-8 read with optional line range and line numbering           |
| `list_directory`| Sorted listing; skips `.git`, `node_modules`, build output        |
| `search_repo`   | Literal search via `git grep` (tracked + untracked text files)   |
| `write_file`    | Create/overwrite with size limits                                |
| `apply_patch`   | Unified diff validated by path jail, then `git apply`            |
| `run_command`   | Allowlisted executable, args passed as argv, **no shell**        |
| `run_tests`     | Configured or auto-detected test command                         |
| `finish`        | Ends the loop with a summary                                     |

Command execution uses `spawn` with `shell: false`, a sanitized environment
(`PATH`, `HOME`, `TMPDIR`, `LANG`, CI flags only), per-command timeouts,
`SIGKILL` on timeout/cancel, and truncated stdout/stderr. Credentials such as
`GITHUB_TOKEN`, `LLM_API_KEY`, and `DATABASE_URL` are not passed to tools.

### LLM tool calling

- `LLMProvider.chatWithTools()` is optional and advertised via
  `supportsToolCalling()`.
- OpenAI implements it with `tools` + `tool_calls`.
- Anthropic implements it with `tools` + `tool_use` / `tool_result` blocks.
- The deterministic `stub` provider deliberately does **not** implement it, so
  coding runs against the stub fail clearly rather than pretending to edit files.
- Requests accept an `AbortSignal`; retries and timeouts are shared through
  `llm/http.ts`.

The registry registers both `research-agent` (API default) and `coding-agent`.
`research-agent` still works with every provider, including the stub.

## 6. Run lifecycle

`apps/api/src/runs/run-service.ts` owns the full lifecycle:

1. Persist the task and run (`running`), create an `AbortController`.
2. Emit `run.started`.
3. If the agent `requiresWorkspace`:
   - `ensureForRun(taskId, runId)`,
   - persist branch/worktree/base branch on the run,
   - emit `workspace.created`.
4. Emit `agent.started`; execute the agent with a context containing task/run
   ids, workspace, cancellation signal, and a progress reporter.
5. Emit `agent.completed` or `agent.failed`.
6. For workspace runs, post-process:
   - generate and persist the diff and changed files,
   - fail with `AGENT_NO_CHANGES` when required and nothing changed,
   - resolve and run tests (or record `skipped` when none is detected),
   - fail with `TESTS_FAILED` when the suite does not pass,
   - stage, commit, persist the SHA, emit `git.commit`,
   - if GitHub is configured: push, emit `git.push`, open a PR, persist the URL,
     emit `github.pr.opened`,
   - if GitHub is not configured: persist an `unavailable` PR artifact and emit
     `github.pr.skipped`; the commit remains local.
7. Optionally remove the worktree according to retention policy
   (`workspace.removed`).
8. Persist the terminal result, set task status:
   - `in_review` when a PR was opened,
   - `completed` for other successful runs,
   - `failed` for failures.
9. Emit `run.completed` or `run.failed` last.

Failure codes include `WORKSPACE_UNAVAILABLE`, `TOOL_CALLING_UNSUPPORTED`,
`AGENT_TOKEN_LIMIT`, `AGENT_TOOL_LIMIT`, `AGENT_MAX_STEPS`, `AGENT_NO_CHANGES`,
`TESTS_FAILED`, `DIFF_FAILED`, `GIT_COMMIT_FAILED`, `GIT_PUSH_FAILED`,
`GITHUB_PR_FAILED`, `CANCELLED`, and `RUN_FAILED`. Failures are persisted with
message, code, and artifacts.

### Cancellation

`POST /runs/:runId/cancel` aborts the run's controller. The agent checks the
signal between model steps; commands and tests are killed with `SIGKILL`; the
run is persisted as failed with `CANCELLED`. Only runs active in the current API
process can be cancelled (`409` otherwise).

### Test runner

`apps/api/src/runs/test-runner.ts`:

- Uses `AGENT_TEST_COMMAND` when set (`parseCommandLine`, no shell).
- Otherwise detects `npm test`, `pytest`, `go test`, or `cargo test`.
- Runs in the worktree with a sanitized environment, a timeout, and cancellation.
- Persists status, command, exit code, durations, stdout, and stderr.

## 7. Events and SSE

New event types:

| Event                | When                                              |
| -------------------- | ------------------------------------------------- |
| `workspace.created`  | Worktree is ready                                 |
| `workspace.removed`  | Worktree was cleaned up                           |
| `agent.started`      | Agent execution begins                            |
| `agent.edit`         | A file was written or patched                     |
| `test.started`       | Automatic tests begin                             |
| `test.completed`     | Automatic tests finish                            |
| `git.commit`         | Commit created (SHA in payload)                   |
| `git.push`           | Branch pushed                                     |
| `github.pr.opened`   | PR created (number and URL in payload)            |
| `github.pr.skipped`  | GitHub unavailable/failed; commit stays local      |

Events are written to `RunEvent` and published to `RunEventBus` in strict order.
The SSE endpoint replays persisted events, then streams live events, with
heartbeats and server-side close on terminal events. Progress callbacks are
chained through one promise so a fast agent cannot reorder events.

Payloads never contain tokens; `push` errors are redacted before persistence.

## 8. GitHub integration

- `GitHubClient` is instantiated only when both `GITHUB_TOKEN` and
  `GITHUB_REPOSITORY` are present.
- The client creates PRs against `GITHUB_BASE_BRANCH` (default `main`) from
  `taskfleet/<runId>`.
- Push uses `GITHUB_REMOTE_URL` when set, otherwise
  `https://github.com/<owner>/<repo>.git`, with the token injected per command.
- Tokens and authenticated URLs are redacted from logs and error messages.
- Missing credentials are reported as unavailable in `/integrations`
  (`tokenConfigured`, `prCreation`) and in the run's PR artifact; no PR is faked.
- Webhook task resolution understands both legacy `taskfleet/<taskId>` branches
  and per-run `taskfleet/<runId>` branches.

`GET /integrations` now also reports `llm.toolCalling`, `llm.live`,
`github.prCreation`, `github.baseBranch`, and the worktrees root.

## 9. API changes

Existing endpoints are unchanged in shape, with additive fields:

- Run DTOs include `branch`, `worktreePath`, `commitSha`, `pullRequestUrl`,
  `baseBranch`, and `artifacts`.
- Task detail run DTOs include the same fields and artifacts.
- Agent DTOs include `requiresWorkspace` and `toolCalling`.
- New: `POST /runs/:runId/cancel` → `202 { success, cancelled }`; `404` for an
  unknown run; `409` when the run already finished or is not active locally.

Artifacts are returned with parsed JSON `data` and text `content`.

## 10. UI changes

- **Run detail** (`WorkspacePanel`): branch, worktree path, base branch, commit
  SHA, PR link or status, changed files with statuses, unified diff with
  add/remove highlighting, test command/status/exit code/duration/stdout/stderr,
  and an explicit GitHub-unavailable/failed reason.
- **Task detail** (`WorkspaceSummary`): compact branch, commit, changed-file
  count, test status, and PR link for the latest run.
- **Run detail polling** refreshes while a run is active so artifacts appear
  without a manual reload; SSE still drives the live timeline.
- **Event timeline** has tones for workspace, edit, test, commit, push, and PR
  events.
- **Agents page** marks agents with `git worktree` and `tool calling` badges.
- **Task dialog** explains that workspace agents run in a worktree and that the
  stub provider does not call a live model.
- All rendering is driven by persisted API data; no mock diffs, branches, or PRs.

## 13. Limitations and security notes

- **Not a container sandbox.** Isolation is filesystem- and Git-level: each run
  gets its own worktree and branch, and paths are jailed. A command run by the
  agent can still access the network and files readable by the API process.
  Docker worker isolation remains planned.
- **Command allowlist is not a security boundary by itself.** Allowlisted
  interpreters (e.g. `node`, `python`) can execute arbitrary code. The allowlist,
  sanitized environment, timeouts, and isolation reduce accidental damage; they
  do not replace containerization.
- **Worktrees are retained by default.** This preserves evidence for review but
  consumes disk. Set `WORKTREE_KEEP_ON_SUCCESS=false` / `WORKTREE_KEEP_ON_FAILURE=false`
  to clean up; branches are kept for pending PRs.
- **Live model quality is not guaranteed.** Limits, tests, and diffs make runs
  observable and falsifiable, but a model can still produce incorrect changes.
- **GitHub credentials are required for push/PR.** Without them, M1 completes a
  local commit and reports PR creation as unavailable.
- **Docker build was not verified locally** (no Docker daemon available).
- **Gitleaks/Semgrep were unavailable locally**; Trivy was verified. This is
  unrelated to M1 but remains true for the security page.

## 14. Manual verification

### Prerequisites

- Node.js 20+ (22 recommended), npm 10+, Git.
- A Git repository (TaskFleet runs against its own checkout by default).
- For live coding: an OpenAI or Anthropic API key.
- For push/PR: a GitHub token with `repo` scope and an `owner/repo` that the
  token can write to.

### Automated checks

```bash
npm install
npm run db:generate
npm run db:push
npm run typecheck
npm test
npm run build
```

### Configure a live run

Copy `.env.example` to `apps/api/.env` and set:

```dotenv
LLM_PROVIDER=openai            # or anthropic
LLM_API_KEY=sk-...             # never commit this file
LLM_MODEL=gpt-4o-mini          # optional

GITHUB_TOKEN=ghp_...
GITHUB_REPOSITORY=owner/repo
GITHUB_BASE_BRANCH=main

WORKTREES_ENABLED=true
```

Start the stack:

```bash
npm run dev       # API on http://127.0.0.1:3000
npm run dev:web   # dashboard on http://localhost:5173
```

### End-to-end coding run

```bash
curl -X POST http://127.0.0.1:3000/api/tasks \
  -H 'content-type: application/json' \
  -d '{
    "prompt": "Add a short M1 verification note to README.md and run the tests.",
    "agentId": "coding-agent",
    "title": "M1 manual verification"
  }'
```

Then:

```bash
# Replace <runId> with the id returned above.
curl -N http://127.0.0.1:3000/api/runs/<runId>/events
curl http://127.0.0.1:3000/api/runs/<runId>
```

Confirm:

1. `branch` is `taskfleet/<runId>` and `worktreePath` exists on disk.
2. `GET /runs/<runId>` includes `diff`, `changed_files`, `test_results`, and
   `git_commit` artifacts.
3. `test_results.status` is `passed`.
4. `commitSha` is a real 40-character SHA (`git show <sha>` works).
5. With GitHub configured, `pullRequestUrl` opens a real PR from
   `taskfleet/<runId>` into `main`, and `github.pr.opened` appears in events.
6. With GitHub **not** configured, the run still commits, the PR artifact says
   `unavailable`, `github.pr.skipped` is emitted, and no URL is fabricated.
7. The dashboard run detail shows branch, worktree, changed files, diff, tests,
   commit, and PR link; the task moves to `in_review` when a PR was opened.

### Cleanup

Worktrees are retained by default:

```bash
git worktree list
git worktree remove --force .taskfleet/worktrees/<runId>
git branch -D taskfleet/<runId>
```

Set `WORKTREE_KEEP_ON_SUCCESS=false` and `WORKTREE_KEEP_ON_FAILURE=false` to let
the orchestrator clean up automatically.
